# Context Map

## Contexts

- [Chat Scroll Viewport](./CONTEXT.md) — anchor-based bidirectional chat list (message-id origin)
- [Panel Catalog Viewport](./docs/panel-catalog/CONTEXT.md) — catalog body of the panel (emoji / stickers / GIFs): sections, leaves, snapshot, glyph atlas
- [Content and Assets](./docs/content/CONTEXT.md) — content identity, collections, data seams, the asset cache and media pipeline
- [Chat Chrome](./docs/chrome/CONTEXT.md) — theme and glass, panel shell and pages, panel presentation, composer, host wiring

## Relationships

- **Chat Scroll ↔ Panel Catalog**: Shared *idea* of **stitch** (far-path continuity illusion). Both bind content through the **asset cache** (Content and Assets): panel grid and chat inline / attachment leaves share it. Different identity and geometry models — do not share message-id origin, chunks, or navigation load-gate.
- **Chat Scroll ↛ Panel Catalog**: Message attachment media (photo/video galleries in the chat) is **not** Panel Catalog. That surface stays under Chat Scroll / future attachment chrome.
- **Chat Scroll → Content and Assets**: Message bodies stay markdown ([ADR 034](docs/adr/034-rich-text-wire-and-persistence.md)); the host runs **entity detection** and the **emoji-only text** classifier from Content and Assets, and inline content reaches bodies through the **inline embed** seam and `ContentEmbed`, never through the panel or data packages ([ADR 017](docs/adr/017-body-linkify-host-invoked.md), [ADR 029](docs/adr/029-host-integration.md), [ADR 036](docs/adr/036-emoji-only-message-presentation.md)). The root package depends on `catalog_assets` and `content_model`.
- **Panel Catalog → Content and Assets**: The viewport renders **catalog leaves** (content key + descriptor facts + host tag) and binds them through the asset cache; it paints the `AssetPaintable` and, where a sprite exists, one batched draw per atlas page ([ADR 022](docs/adr/022-asset-cache-and-media-pipeline.md), [ADR 024](docs/adr/024-panel-catalog-seams.md)). It never imports atlas types and does not depend on Chat Chrome.
- **Chat Chrome → Panel Catalog**: Pages host the viewport, adapt chrome tokens to the **panel catalog theme**, turn **collections** into **catalog snapshots**, and handle leaf hits and near-viewport events. Category jumps call `PanelCatalogController.jumpToSection`; hosts gate strip sync on `isSectionJumpActive`. Glossary: *Catalog page*, *Panel catalog theme*, *Section jump*, *Leaf hit*.
- **Chat Chrome → Content and Assets**: The shell, pages and composer depend on `content_model` seams (sources, stores), use `package:listen` for change notification and, for pages and the composer, depend on the asset cache. The shell and presentation never depend on data payloads, codecs or fetchers.
- **Chat Chrome ↔ host**: The host owns the composition root, aggregates composer extent and presentation **occupancy** into the viewport padding ([host insets](docs/architecture/14-host-chrome-insets.md)), and handles the single **panel event** type.
- **Packages**: Repo-root `packages/` holds the shared ecosystem libs — `content_model`, `chrome_foundation`, `catalog_assets`, `panel_catalog`, `emoji_data`, `emoji_catalog_pack`, `kv_shared_preferences`, `rich_clipboard`, `panel_shell`, `panel_pages`, `panel_presentation`, `composer_editable`, `chat_composer`, `image_decoder` — in the dependency direction fixed by [ADR 020](docs/adr/020-package-topology.md): two leaves depend on nothing (and `composer_editable` on the SDK only), no package re-exports another, and the shell, pages and presentation never reach payloads or codecs. There is no umbrella package. `keyboard_insets*` stay under `example/packages`. `chat_scroll_view` remains at repo root and owns markdown **text selection** ([ADR 013](./docs/adr/013-viewport-owns-markdown-text-selection.md)); the former transitional `packages/chat_md_selection` has been fully absorbed into that core and deleted. `example/` is the app only.
- **ADR**: [006 — Panel Catalog Viewport](./docs/adr/006-panel-catalog-viewport.md) (amended by 020, 022, 024); 020–031 for the package-architecture decisions, 032–038 for rich text (clipboard, code blocks, wire contract, markdown engine fork, emoji-only bodies, spoiler and mention styles, composer editable).
- **Placeholder TRACE**: [docs/panel-catalog/leaf-placeholder.md](./docs/panel-catalog/leaf-placeholder.md) — circle vs thumb-first vs shaped wash.
